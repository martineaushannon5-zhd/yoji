# 工作流 06：项目完善路线图

> 记录时间：2026-11-11
> 触发问题：`/api/` 打不开、要不要写 FastAPI 式文档、功能不够、鸿蒙没做沉浸式、后台与桌面端太浅。

## 0. 结论先说

- `/api/` 打不开是因为后端**没有根路由**，请求落到最后的 404 处理，返回 `{"code":404,"message":"接口不存在"}`。这不是故障，但确实该补一个索引页。
- 文档**有必要**，但不要手写 markdown 当唯一来源——手写的会过期。已加 OpenAPI：`/api`（索引）、`/api/openapi.json`（规范）、`/api/docs`（Swagger UI），行为对齐 FastAPI。
- 真正的短板不是「接口数量」，而是**产品闭环**：学习算法、内容生产、运营工具、客户端体验。下面按优先级列。

## 2. 鸿蒙端：现状与适配方案

事实（已核对）：

- `build-profile.json5`：`targetSdkVersion 6.1.1(24)`、`compatibleSdkVersion 5.0.2(14)`。
- `entry/src/main/ets/entryability/EntryAbility.ets`：只 `loadContent('pages/SplashPage')`，**没有** `setWindowLayoutFullScreen`，也没有读避让区。
- `Index.ets` 底部导航是自绘 `@Builder TabBar()`（Stack 悬浮胶囊 + 拖拽指示器 + 滚动联动），只有根节点 `.expandSafeArea(BOTTOM)`。
- 华为 HDS 组件确实可用：`@kit.UIDesignKit` 导出 `HdsNavigation / HdsTabs / HdsNavigationTitleBarStyle / HdsTabsFloatingStyle` 等，SDK 声明在 `sdk/default/hms/ets/api/@hms.hds.hdsBaseComponent.d.ets`，**`@since 6.0.0(20)`**。

这意味着：

- 直接换 `HdsTabs`：必须把 `compatibleSdkVersion` 提到 20（HarmonyOS 6.0），否则 5.x 设备运行时找不到 hms 实现 → 崩溃。要么放弃 5.x，要么运行时判断 + 两套实现。
- 现有自绘 TabBar 交互（拖拽指示器、滚动收起、玻璃材质）其实已经超过系统默认 TabBar 的表现力；换 HdsTabs 的收益主要是**系统级动效、折叠大标题、深浅色材质、无障碍语义**。视觉上大概率会变得更「原生」，但会丢掉现在的手势彩蛋。

推荐分两步：

**第一步（低风险，先做）真沉浸式**

1. `EntryAbility.onWindowStageCreate`：`windowStage.getMainWindowSync().setWindowLayoutFullScreen(true)`；
2. 读 `window.getWindowAvoidArea(TYPE_SYSTEM / TYPE_NAVIGATION_INDICATOR)`，把 `statusBarHeight`、`navBarHeight`、`bottomBarHeight` 写进 `AppStorage`；
3. 各页根容器顶部加 `statusBarHeight` 的 padding，滚动容器底部加 `navBarHeight`；TabBar 的 `margin.bottom` 改为 `navBarHeight + 8`；
4. 系统栏透明 + 内容色跟随深色模式（`setWindowSystemBarProperties`）；
5. 页面返回前台时重新读取避让区（折叠屏展开/旋转会变）。

**第二步（体验升级，需真机回归）换 HDS**

- 用 `HdsNavigation` 承载页面级导航（大标题、返回按钮、菜单），`HdsTabs` 承载底部三栏；
- 保留现有玻璃色板，但用 `HdsTabsFloatingStyle` + `SystemMaterialParams` 做材质，减少自绘阴影；
- `compatibleSdkVersion` 提升到 20，或写 `canIUse('SystemCapability...')` 降级分支；
- 折叠屏/平板：`HdsNavigation` 的 `NavBarWidthRange` 做分栏。

## 4. 后台：从「能用」到「合格」

现状其实不差：JWT、限流、helmet、统一错误码、分页搜索、词库导入、视频上传（900MB）、媒体同步脚本都有。缺的是**运营深度**：

1. **角色与审计**：现在只有单一管理员。加 `roles`（超管/运营/只读）、`audit_logs`（谁在什么时间删了哪个用户/视频），删除操作必须留痕。
2. **数据看板**：`/api/admin/stats` 只有 14 天趋势的骨架；补 DAU/WAU、次日留存、人均学习词数、完课率、视频完播率，支持时间范围筛选与 CSV 导出。
3. **内容工作流**：词库可视化编辑（增删改词条，不必每次重传整本）、视频转码状态与封面裁剪、拖拽排序、批量上下架。
4. **发布与回滚**：词库版本号 + 历史版本回滚；视频换源不影响已有记录。
5. **系统工具**：健康页（DB 大小、媒体占用、最近错误）、后台任务队列（导入/转码）、日志查看、数据库备份下载。
6. **体验**：全局 loading/空态/错误边界、表单校验、危险操作二次确认、快捷键、暗色模式（现在只有浅色）。

## 5. 桌面端：从「能打开」到「像个桌面应用」

已完成：自定义 `app://` 协议、asar 1.8MB、包 113MB、安装验证通过。

待补：

1. **自动更新**：`electron-updater` + 静态 `latest.yml`，启动静默检查，托盘提示重启；
2. **系统集成**：托盘菜单、单实例锁、开机自启、窗口尺寸记忆、`Ctrl+R` 刷新 / `F12` 仅开发可用；
3. **离线与网络**：断网时给出明确提示而不是白屏；静态资源本地化（已满足）；
4. **安全**：`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`（当前 main.js 是纯加载器，确认默认值）、生产禁用 devtools；
5. **签名**：Windows 代码签名证书，避免 SmartScreen 拦截（学生项目可先用自签名 + 说明）；
6. **多窗口/导出**：用户详情独立窗口、表格导出 CSV/Excel。

## 6. 建议实施顺序

1. **本周**：接口文档收尾（已完成）+ 鸿蒙真沉浸式（第一步）+ 桌面端自动更新骨架。
2. **下一阶段**：SRS 学习算法 + 词库例句（CET4/CET6）+ 错词本/小测。
3. **再下一阶段**：后台 RBAC + 审计日志 + 看板指标 + 词库可视化编辑。
4. **收尾**：离线缓存、推送、成就体系、桌面端签名与托盘。

每项都可以独立发版，不需要一次做完。
