# 工作流 01：项目规划与技术选型

## 1. 项目目标
为了丰富毕业作品集，我们计划将现有的 Next.js Web 管理后台（`yoji-admin`）打包为 Windows 桌面应用程序。这样一来，整个项目生态将包含：
- **Web 端**：自习室预约系统、个人博客
- **移动端**：基于 ArkTS/ArkUI 的鸿蒙 App
- **桌面端**：基于 Electron + Next.js 的 Windows 管理应用
- **云端**：Node.js 部署在公网服务器，提供统一 API

## 2. 技术选型：Electron + Next.js
选用 Electron 的原因：
1. **复用现有资产**：直接复用 `yoji-admin` 现有的 React/Next.js 代码，避免从零开发 UI。
2. **技术栈匹配**：Electron 是前端开发人员必备的跨端桌面开发技术（VS Code, 飞书, Discord 等均基于此）。
3. **视觉与交互**：满足“可视化管理”的需求，且具备原生桌面应用的体验。

## 4. 后续执行步骤
1. **环境检查**：检查 `yoji-admin` 的 Next.js 配置，评估集成 Electron 的最佳方案（Static Export 或 本地服务模式）。
2. **依赖安装**：在项目中安装 `electron`、`electron-builder`、`concurrently` 等依赖。
3. **主进程开发**：编写 Electron 的主进程（Main Process）代码，用于创建应用窗口、处理系统托盘等。
4. **开发联调**：配置双端热更新（Next.js 服务 + Electron 窗口）。
5. **打包分发**：配置打包脚本，最终生成 Windows 的 `.exe` 安装包。
