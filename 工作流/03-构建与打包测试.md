# 工作流 03：构建、打包与安装验证

> 记录时间：2026-11-11
> 目标：修掉主进程 `Cannot find module 'electron-serve'`，把安装包从 169MB 压下来，并完整验证「打包 → 安装 → 启动 → 渲染 → 接口」链路。

## 1. 问题回顾

安装版启动即弹：

```
A JavaScript error occurred in the main process
Uncaught Exception:
Error: Cannot find module 'electron-serve'
Require stack:
- ...\resources\app.asar\main.js
```

两个叠加原因：

1. `main.js` 用 `require("electron-serve")`，但 `electron-serve@3.0.1` 是**纯 ESM** 包（`"type": "module"`），CommonJS 的 `require` 本来就加载不了它；在 Node 22+ 下会直接抛 `require() of ES Module ... not supported`。
2. 它被放在 `devDependencies`，而 electron-builder 默认**只把生产依赖打进 asar**。所以即使能 `require`，运行包里也根本没有这个模块。

## 2. 修复方案（已落地）

### 2.1 去掉 electron-serve，改用内置自定义协议

`main.js` 用 Electron 自带的 `protocol.handle` 注册 `app://` 协议，直接托管 `out/` 静态目录：

```js
protocol.registerSchemesAsPrivileged([{ scheme: "app", privileges: { standard: true, secure: true, supportFetchAPI: true } }]);
// ready 之后
protocol.handle("app", async (request) => {
  const url = new URL(request.url);
  const filePath = resolveFile(url.pathname);      // 目录 -> index.html，越界 404
  return net.fetch(pathToFileURL(filePath).toString());
});
window.loadURL("app://-/");                        // 生产
```

`resolveFile` 的规则与 electron-serve 对齐：目录补 `index.html`；带扩展名却找不到 → 404；无扩展名找不到 → 回退 `index.html`（给前端路由）；`path.relative` 校验防目录穿越。开发模式仍然加载 `http://localhost:3000`。

### 2.2 打包配置瘦身

- 全部原 `dependencies` 移入 `devDependencies`：静态导出后的 `out/` 是纯 HTML/JS/CSS，运行时不需要任何 node_modules。
- `build.files` 只保留 `out/**/*`、`main.js`、`package.json`。
- `asar: true`、`compression: "maximum"`、`electronLanguages: ["zh-CN","en-US"]`（只保留中文和英文语言包）。
- 输出目录：`dist-installer`（旧的 `dist-electron` 已作废，见 §5）。
- 构建脚本去掉硬编码的 `LOCALAPPDATA` 绝对路径，只保留镜像变量：

```
cross-env NEXT_PUBLIC_API_ORIGIN=https://yoji.zhdstudy.cyou npm run build
&& cross-env ELECTRON_MIRROR=... ELECTRON_BUILDER_BINARIES_MIRROR=... electron-builder
```

## 3. 优化前后对比

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| `app.asar` | 151,033,584 B（17,785 个 node_modules 文件） | **1,885,323 B（80 个条目）** |
| 安装包 | 169,004,548 B | **113,363,323 B** |
| 解包目录 | 631 MB | 311 MB |
| 安装/启动 | 解压上万个小文件，慢 | 只解压 80 个条目，明显变快 |

体积大头现在是 Electron 本体（`Yoji Admin.exe` 约 239MB、dxcompiler 25MB、resources.pak 13MB、icudtl 11MB），这部分是运行时，压不下去；能压的 node_modules 已经从 150MB 降到 1.8MB。

2. `electron-builder`：产出 `dist-installer/Yoji Admin Setup 0.1.0.exe`（113MB）。

## 5. 踩过的坑

### 5.1 工作区被打了 Low 完整性标签，NSIS 打包失败

现象：`electron-builder` 到最后一步报 `Yoji Admin Setup 0.1.0.exe process failed 2`；换输出目录后 7za 报 `cannot open file ... 拒绝访问`。

排查：`icacls` 显示项目根带 `Everyone:(CI)(DENY)(S,DC)`，整棵树带 `Mandatory Label\Low Mandatory Level`（旧沙箱工具留下的）。低完整性进程（`%TEMP%` 下的 7za、NSIS stub）无法写入 Medium 完整性的目录，写 uninstaller 失败 → NSIS 退出码 2。

处理：

```bat
icacls . /remove:d Everyone
icacls <项目根> /setintegritylevel "(OI)(CI)M" /T /C /Q
```

之后打包一次通过。

### 5.2 本机 shell 里 `ELECTRON_RUN_AS_NODE=1`

直接跑 `Yoji Admin.exe` 会变成 Node 进程（`--version` 打印 `v24.x`），不会开窗口。验证时要：

```bash
env -u ELECTRON_RUN_AS_NODE "./Yoji Admin.exe" --remote-debugging-port=9222
```

### 5.3 跨域资源 `transferSize` 为 0 ≠ 加载失败

CDP 里查 `performance.getEntriesByType("resource")`，跨域图片/接口的 `transferSize`、`decodedBodySize` 都是 0（缺 `Timing-Allow-Origin`），不能用它判断失败；应查 `img.naturalWidth`、`img.complete`。

### 5.4 旧包删不掉

`dist-electron/resources/app.asar` 被 `Trae.exe`、`DeepSeek Harness.exe` 持有句柄，`rm -rf` 报 `Device or resource busy`。旧目录保留即可，新包在 `dist-installer`，`package.json` 已指向新目录。

## 6. 面试亮点

- **跨端复用**：一套 Next.js 代码同时产出 Web 站和离线桌面端，静态导出 + 自定义协议零服务端依赖。
- **问题定位深度**：从「缺模块」追到 ESM/CJS 与依赖分层，再追到文件系统完整性标签导致的 NSIS 失败。
- **工程化**：打包体积 169MB → 113MB，asar 151MB → 1.8MB；镜像、语言包、压缩级别、输出目录都做了约束。
- **可验证**：用 CDP 做启动后的自动化验收（标题、路由、图片、接口），而不是只看「装上了」。
