# 15 · 后台「词库同步」：让源码自部署实例一键拿到线上词库

## 背景

从 GitHub / Gitee 克隆源码自部署时，仓库里只有 `server/scripts/` 下的少量内置词表，**不含线上 SQLite 数据库**，于是新实例启动后 App 只能看到 1–2 本词库。

这个板块解决“克隆之后没有内容”的冷启动问题：在管理端点一下，从官方节点拉取全部词库并写入当前实例的数据库。

它不是“让浏览器直接连线上数据库”（SQLite 没有网络协议，浏览器也拿不到文件），而是：

```
自部署实例管理端  --POST /api/admin/wordbooks/sync-->  自部署后端
                                                    --GET 官方 /api/wordbooks/full-->  yoji.zhdstudy.cyou
                                                    <--JSON（8 本 / 约 6MB）--
                                          写入本地 SQLite（按 id 整本覆盖）
```

## 后端

### 配置（`server/src/config.js`）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `OFFICIAL_WORDBOOKS_URL` | `https://yoji.zhdstudy.cyou/api/wordbooks/full` | 官方词库全量地址 |
| `WORDBOOK_SYNC_MAX_BYTES` | `41943040`（40MB） | 单次响应上限 |
| `WORDBOOK_SYNC_TIMEOUT_MS` | `30000` | 拉取超时 |

### 接口

`POST /api/admin/wordbooks/sync`（需管理员 JWT）

```json
{ "url": "https://其他可信实例/api/wordbooks/full" }   // url 可省略
```

响应：

```json
{
  "code": 0,
  "data": {
    "source": "https://yoji.zhdstudy.cyou/api/wordbooks/full",
    "imported": [{ "id": "cet4-6", "name": "四六级核心词汇", "words": 6911 }],
    "skipped": [{ "id": "xxx", "reason": "没有有效单词" }],
    "totalBooks": 8,
    "totalWords": 37950,
    "skippedWords": 1287,
    "elapsedMs": 925
  }
}
```

实现要点（`server/src/routes/adminWordbooks.js`）：

- **只允许 http/https**，`isPrivateHostname()` 拒绝 `localhost`、`127.0.0.1`、`10.x`、`192.168.x`、`172.16–31.x`、`169.254.x`、`.internal`、`.local`，避免把服务端当 SSRF 跳板。
- `AbortController` + 30s 超时；先看 `content-length`，再按实际 body 长度二次校验，均不得超过 40MB。
- 兼容三种载荷：`{data:{books}}`、`{books}`、直接数组。
- 每条词校验 `word` 与 `meaning`，缺任一则丢弃并计数；缺 `id` 补 `<bookId>-w0001`。
- 复用 `saveWordBook()` 按 id 整本 upsert；已存在的词库保留本地 `visible`，不把用户下架的书重新上架。
- 审计日志记 `wordbook.sync`，detail 为“N 本 / M 词”。

### 为什么导入数少于官方总数

官方 `/full` 共 39,237 词，但其中 1,287 条 `meaning` 为空（如 `cet4-6` 的 `an`），导入时被丢弃，故本地为 37,950。空释义的卡片没有学习价值，宁可不要。

## 前端

- 路由：`/sync`，菜单名“词库同步”，图标 `ri:cloud-download-line`，位于“词库管理”之后。
- 页面：`yoji-admin-v2/src/views/yoji/sync/index.vue`
  - 说明区：为什么需要、覆盖而非追加、40MB/超时限制。
  - 来源输入框（默认官方地址，可改成其他可信实例）。
  - 同步结果表：词库 / id / 词数；底部汇总“N 本 · M 词 · 跳过 K 条无释义 · 耗时”。
  - 本地现状三卡：词库数 / 词条数 / 最近同步时间（`localStorage.yoji_wordbook_sync_at`）。
- 词库管理页右上角新增“从官方同步”按钮，直接跳 `/sync`。
- API：`yoji-admin-v2/src/api/yoji.ts` 的 `syncWordbooks(url?)`，类型 `SyncResult`。

## 本地验证

```bash
cd server
PORT=3099 DATA_DIR=.tmp-sync node src/server.js
# 另开一个终端
TOKEN=$(curl -s -X POST localhost:3099/api/admin/login -H 'content-type: application/json' \
  -d '{"account":"admin","password":"test123"}' | jq -r .data.token)
curl -s -X POST localhost:3099/api/admin/wordbooks/sync \
  -H "authorization: Bearer $TOKEN" -H 'content-type: application/json' -d '{}'
```

结果：8 本 / 37,950 词 / 925ms。线上接口验证：无 token 返回 401；`/api/openapi.json` paths 34，含 `/api/admin/wordbooks/sync`。

## 部署

```bash
# 后端 4 个文件
tar czf /tmp/sync-be.tgz src/config.js src/http.js src/openapi.js src/routes/adminWordbooks.js
scp /tmp/sync-be.tgz root@120.24.171.99:/tmp/
ssh root@120.24.171.99 'tar xzf /tmp/sync-be.tgz -C /www/wwwroot/yoji/server && \
  chown -R www:www /www/wwwroot/yoji/server/src && \
  export PATH=/www/server/nodejs/v24.22.0/bin:$PATH && pm2 restart yoji_project'

# 前端
tar czf /tmp/y2.tgz -C dist . && scp /tmp/y2.tgz root@120.24.171.99:/tmp/
ssh root@120.24.171.99 'rm -rf /www/wwwroot/yoji-admin/* && tar xzf /tmp/y2.tgz -C /www/wwwroot/yoji-admin && \
  chown -R www:www /www/wwwroot/yoji-admin'
```

## 回滚

- 后端：`/root/backups/yoji-server-before-sync-*.tgz` 覆盖回 `src/`，重启 PM2。
- 前端：`/root/backups/yoji-admin-before-sync-button-*.tgz` 解压回 `/www/wwwroot/yoji-admin`。
- 数据：同步是“按 id 整本覆盖”，回滚代码不会回滚词库；若不想要新导入的书，在词库管理页删除即可，或从 `/root/backups/yoji.db.*` 恢复数据库。

## 已知限制

- 只做整本覆盖，不支持“只同步某几本”或增量合并。
- 同步是同步阻塞请求（8 本约 1 秒）；词库继续变大后建议改成后台任务 + 进度轮询。
- 不校验远端内容签名；只应填可信实例地址（默认官方节点）。
- 跳过空释义词条（见上），所以导入数会小于官方 `/full` 的总数。
- `url` 一旦指向恶意实例，对方可写入任意词库内容（但仅限词库表），仍建议保持默认。

## 后续可做
