# 工作流 05：词库上传排障与「例句 / 词组」扩展方案

> 记录时间：2026-11-11
> 起因：把 `english-wordlists-master.zip` 上传到 https://yoji.zhdstudy.cyou/wordbooks/ 时「没有一个成功」；视频能上传并实时出现在 App，词库不行。另问：给背单词卡片加词组/例句是否可行、工作量多大。

## 1. 上传为什么失败（按可能性排序）

后台词库接口在 `server/src/routes/adminWordbooks.js`，规则很明确：

- 一次只收**一个文件**，扩展名只能是 `.txt` 或 `.json`（`fileFilter` 直接拦截其余类型）。
- 大小上限 8MB（multer `limits.fileSize`）。
- 需要管理员 JWT（`Authorization: Bearer <token>`，12 小时过期）。
- 解析失败会返回「没有解析到单词，请检查文件格式」。

对应到这次操作：

| 现象 | 原因 |
| --- | --- |
| 选的是 `english-wordlists-master.zip` | zip 不在白名单，直接报「只支持 .txt 或 .json 词表」 |
| 选的是压缩包里的 PDF / XLSX / DOCX | 同上，全部被扩展名拦截 |
| 登录很久后再传 | 管理员 token 过期，返回 401，页面提示登录失效 |
| 上传成功但 App 没变 | App 只在**启动时**（`SplashPage`）或**手动点刷新**（词书页）拉 `/api/wordbooks/full`；后台传完不会推送 |

正确做法：把 zip 解压，取里面的 `CET4_edited.txt` 这类**纯文本**逐个上传。该文件的格式是

```
abandon [əˈbændən] vt.丢弃；放弃，抛弃
```

与 `server/src/wordlist-parse.js` 的 `WORD_RE` 完全兼容，能正确解析出单词、音标、释义。

## 2. 上传后的行为

- 词表 id 由文件名 slug 生成（小写字母/数字/`_`/`-`，2–64 位），例如 `CET4_edited.txt` → `cet4_edited`。
- **按 id 整本替换**：同 id 再传一次会覆盖整本词表，不是增量追加。
- `.txt` 解析出来的词条 `example` / `exampleCn` 为空；只有 `.json` 能带例句。
- 现有线上 7 本（脚本导入）：cet4 4538、cet6 2220、cet4-6 8013、highschool 3445、npee 5392、toefl 4510、gre 7729。

## 3. 加例句 / 词组：可行，但要做数据

代码链路其实已经通了：

- `entry/src/main/ets/model/WordModel.ets` 的 `Word` 已有 `example`、`exampleCn`；
- `entry/src/main/ets/pages/LearnPage.ets:357-365` 卡片已经渲染这两行；
- `entry/src/main/ets/common/Api.ets:395-402` 会映射接口里的 `example` 字段；
- 后台 `normalizeJsonWords` 也保留 `example` / `exampleCn`。

缺的是**数据**和**词组字段**：

1. **例句**：生成 `{ word, phonetic, meaning, example, exampleCn }` 的 JSON，按词表 id 上传覆盖。注意整本替换，JSON 里必须包含该词表的全部单词，否则会「传一本少一本」。
2. **词组**：需要新增 `phrases: [{ en, cn }]` 字段，改动点：`WordModel.ets`、`Api.ets` 映射、`wordlist-parse.js`（JSON 校验）、后台词表预览、`LearnPage` 卡片渲染（词组列表 + 折叠）。属于「小改动、全链路」，约半天到一天。
3. **体积**：`/api/wordbooks/full` 现在约 5–6MB，全部词加例句后可能到 9–10MB。App 启动时一次性拉全量会明显变慢。建议：
   - 先只给 CET4 / CET6 加例句；
   - 或把接口拆成「词表列表 + 按 id 拉词条」，按需加载；
   - 或给 `full` 加 gzip / 分页。

## 4. 建议的落地顺序

1. 先确认这次报错的红字原文（是扩展名错、401，还是解析失败），对症处理。
2. 用 `CET4_edited.txt` 单文件上传一次，验证「上传 → 点刷新 → App 出现新词书」。
3. 做 100 词的例句 JSON 小样，走一遍 `.json` 上传，确认卡片能显示例句。
4. 小样没问题再批量生成，按词表分批上传（每本单独一个 JSON）。
5. 词组作为第二阶段，先定 JSON 结构再改客户端。

## 5. 备注

- 线上部署在宝塔，媒体/数据目录见 `docs/baota-notes.md`；词库数据在 SQLite（`server/src/db.js`），换库前先备份。
- 后台页面本身没有「上传进度」之外的实时通知，App 端加一个「词库版本号」轮询会更顺手，但不是必须。
