# 07 - 鸿蒙沉浸式适配（状态栏 / 底部导航条）

## 背景

用户反馈（2026-11-11）：App 顶部、底部都没有沉浸式，状态栏和底部手势条是系统默认的白色/黑色条带，和页面背景割裂；底部 tabbar 是自绘组件，问能不能换成华为 `HdsNavigation` / `HdsTabs`。

## 结论先说

- **HDS 组件暂时用不了**：`HdsTabs` / `HdsNavigation` 定义在 `@kit.UIDesignKit`（`@hms.hds.hdsBaseComponent.d.ets`），标注 `@since 6.0.0(20)`。本项目 `build-profile.json5` 的 `compatibleSdkVersion` 是 5.0.2(14)，一旦调用，5.x 设备会直接崩溃。要用必须把最低兼容版本提到 API 20，等于放弃 5.x 用户，不能顺手改。
- 自绘 tabbar 本身交互（胶囊拖拽、滚动收起）已经比较完整，短期保留，只做沉浸式避让。

## 实现

新增 `entry/src/main/ets/common/Immersive.ets`：

| 导出 | 作用 |
| --- | --- |
| `enterImmersive(ctx, dark)` | `setWindowLayoutFullScreen(true)`；状态栏/导航条设为 `#00000000`；系统栏图标颜色随深色模式切换；读取 `getWindowAvoidArea(TYPE_SYSTEM / TYPE_NAVIGATION_INDICATOR)`，把高度（px）写入 AppStorage |
| `exitImmersive(ctx)` | 关闭全屏并把两个 inset 归零 |
| `refreshBarStyle(ctx, dark)` | 只更新系统栏图标颜色，不重算避让区 |

AppStorage 键：`insetStatusBarPx`、`insetNavBarPx`。

`entry/src/main/ets/pages/Index.ets`：

- 引入 `@StorageProp('insetStatusBarPx')` / `@StorageProp('insetNavBarPx')`；
- `aboutToAppear` 和 `onPageShow` 调 `enterImmersive`（从详情页返回时重新开启）；
- `onPageHide` 调 `exitImmersive`（详情页仍是系统默认布局，不需要逐页改 padding）；
- `isDark` 加 `@Watch('onDarkModeChange')`，切换时调 `refreshBarStyle`；
- 内容列 `.padding({ top: px2vp(this.insetStatusPx) })`；
- 根 Stack `.expandSafeArea([SYSTEM], [TOP, BOTTOM])`，让背景色铺到状态栏和手势条后面；
- tabbar 的 `.margin({ bottom: -10 })` 改成 `px2vp(this.insetNavPx) + 6`，抬到手势条上方。

## 验证方式

之前 `hvigorw assembleHap` 只跑到 `CompileArkTS`，`PackageHap` 报 `spawn java ENOENT`。原因是 hvigor 打包阶段直接找 `java` 命令，不认 DevEco 自带的 JBR。把 JBR 加进 PATH 后完整打包成功：

```bash
export JAVA_HOME="C:\\Program Files\\Huawei\\huawei\\DevEco Studio\\jbr"
export PATH="/c/Program Files/Huawei/huawei/DevEco Studio/jbr/bin:$PATH"
"C:/Program Files/Huawei/huawei/DevEco Studio/tools/hvigor/bin/hvigorw.bat" \
  assembleHap --mode module -p product=default -p buildMode=debug --no-daemon
# BUILD SUCCESSFUL
# 产物：entry/build/default/outputs/default/entry-default-unsigned.hap
```

本次改动编译通过，只有 `ProfileEditPage.ets` 既有的 showToast/back deprecated 警告。
真机/模拟器验证需要签名（`SignHap` 提示没有 signingConfigs），且当前 `hdc list targets` 为空，所以本次只做到编译验证。

## 已知限制 / 下一步

1. 目前只有首页开启沉浸式，详情页仍是系统默认布局。要做全应用沉浸式，需要全局开启并在每个页面加顶部留白（12 个页面），再统一处理键盘避让。
2. 页面切换时全屏开关会触发一次窗口尺寸变化，低端机可能看到轻微跳动；全局方案落地后这个跳动会消失。
3. 想要更原生的底部导航，可在兼容版本提到 API 20 后换 `HdsTabs`；迁移时自绘 tabbar 的拖拽/收起逻辑要重写。
